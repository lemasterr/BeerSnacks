# Beer&Snacks — состояние проекта и как продолжить

Последнее обновление: 11.11.2026.

## Что где
- **Сайт:** https://beersnacks.pages.dev. Это Cloudflare Pages, проект `beersnacks`. Каждый push в `main` публикуется автоматически, push в любую другую ветку создаёт тестовый адрес `https://<ветка>.beersnacks.pages.dev`. На тестовом адресе нет базы, поэтому каталог там берётся из `public/data/*.json`, а админка не работает.
- **База:** Cloudflare KV `beersnacks-prod-database` (binding `DB_KV`). Ключи:
  - `catalog:compiled` — все товары, единственный источник данных;
  - `site:categories`, `site:translations`, `site:settings`;
  - `session:*` — входы в админку;
  - `ratelimit:*` — защита от подбора пароля.
  - Старые ключи `product:*` и `catalog:index` больше не используются.
- **Фото товаров:**
  - `public/img/products/*.webp` — обычные файлы сайта, это бесплатно и без лимитов;
  - фото, загруженные через админку, хранятся в R2 `beersnacks-images` и отдаются сайтом по адресу `/media/<имя>`. Публичная ссылка `r2.dev` отключена.
- **Админка:** https://beersnacks.pages.dev/admin. Пароль хранится в переменной `ADMIN_PASSWORD` (Cloudflare → Pages → beersnacks → Settings → Variables).

## Запуск на другом компьютере
```bash
git clone https://github.com/lemasterr/BeerSnacks.git
cd BeerSnacks
npm install
npx wrangler login
cp wrangler.toml.example wrangler.toml
echo "ADMIN_PASSWORD=любой-локальный-пароль" > .dev.vars
npx wrangler pages dev public
```
В `wrangler.toml` впиши id базы: `1673893bd1e04f2380804dc7263ea4b3`. Локальный сервер работает с локальной копией KV в `.wrangler/state`, а не с живой базой. Чтобы залить в локальную базу текущий каталог:
```bash
npx wrangler kv key put catalog:compiled --path public/data/catalog.json --binding DB_KV --local
```

## Что сделано
- **Новый дизайн:** «магазинная полка», шрифты Unbounded + Golos Text, поиск, карточка товара по нажатию, статус «открыто сейчас», светлая и тёмная тема.
- **Исправления безопасности и ошибок:**
  - убран публичный `/api/seed`, через который любой мог стереть каталог;
  - исправлено «сохранил, а на сайте старое» (eventual consistency в KV);
  - цены и поля товаров проверяются и приводятся к правильному типу;
  - защита от CSRF;
  - загрузка SVG запрещена;
  - у загруженных фото уникальные имена: раньше файлы с кириллицей в названии затирали друг друга.
- **Скорость:** вместо PNG на 105 МБ теперь WebP на ~10 МБ, весь каталог отдаётся одним запросом `/api/site` с кешем на 60 секунд.
- **Каталог:** 576 товаров, из них 378 новых с полочных фото. Тексты на uk/en/et/ru, категория «Продукты», цена за кг или 100 г (`price_unit`), две цены у разливного (`price_05` за 0,5 л и `price` за 1 л).
- **Админка** сама сжимает фото с телефона в WebP перед загрузкой.

## Инструменты (`pipeline/`)
- `tools/build_catalog.py` — собирает каталог из живой базы, распознанных товаров (`data/final_products.json`) и текстов.
- `tools/finalize_images.py` — делает из скачанного фото WebP: убирает белый фон и водяные значки, обрезает по товару.
- `tools/defringe.py` — убирает светлую кайму по краю вырезанных товаров.
- `tools/remove.mjs` + `harden.py` — удаление фона нейросетью (npm `@imgly/background-removal-node`) для вырезки товара со своих фото.
- `review/` — локальная страница для проверки цен и названий (`python review/server.py` → http://127.0.0.1:8800).
- `data/*.md` — инструкции для ИИ-агентов: распознавание фото, тексты, поиск фото товаров.
